== Allgemeine Informationen

=== Testumgebung
* *Framework:* Jest (Version 29+) mit React Native Testing Library
* *Test Runner:* Jest mit Expo-Preset
* *Sprache:* TypeScript/JavaScript
* *CI/CD:* Lokale Ausführung, geplant für GitHub Actions

=== Testausführung
[cols="1,3"]
|===
|Kommando |Beschreibung

|`npm test`
|Führt alle Tests einmalig aus

|`npm run test:watch`
|Führt Tests im Watch-Modus aus (bei Dateiänderungen)

|`npm run test:coverage`
|Führt Tests aus und erstellt Coverage-Report
|===

=== Teststruktur
Tests befinden sich in `__tests__/`-Ordnern neben den zu testenden Dateien:

* `src/components/buttons/__tests__/` - Komponententests für Buttons
* `src/components/input/__tests__/` - Komponententests für Input-Felder
* `src/utils/__tests__/` - Tests für Hilfsfunktionen
* `src/db/queries/__tests__/` - Tests für Datenbankabfragen

== Testkonzept

=== Testobjekte (Testpyramide)

==== Unit Tests (Basis)
Unit Tests bilden die Basis der Testpyramide und testen einzelne Funktionen und Komponenten isoliert.

*Getestete Komponenten:*

* *UI-Komponenten:* Button, TextField
* *Utility-Funktionen:* calculateTotalAmount, dateFromString
* *Datenbank-Queries:* Category, Transaction, TransactionGroup, Budget

==== Integrationstests (geplant)
* Integration von Komponenten mit Redux/Context
* Datenbank-Operationen mit tatsächlichen Daten
* API-Integration (Gemini AI)

==== End-to-End Tests (geplant)
* Vollständige User Flows
* Navigation zwischen Screens
* Komplette Transaktionserstellung

=== Testmethoden

==== Verwendete Testmethoden
[cols="1,3"]
|===
|Methode |Beschreibung

|*Render Tests*
|Testen, ob Komponenten korrekt gerendert werden mit verschiedenen Props

|*Interaction Tests*
|Testen von Benutzerinteraktionen (Klicks, Eingaben)

|*Unit Tests*
|Testen isolierter Funktionen mit verschiedenen Eingabewerten

|*Mocking*
|Simulieren von Datenbankabfragen und externen Abhängigkeiten
|===

==== Test-Tools
* *React Native Testing Library:* `render()`, `fireEvent`, `waitFor()`
* *Jest Matchers:* `toBe()`, `toEqual()`, `toBeInstanceOf()`
* *Jest Mocks:* `jest.fn()`, `jest.mock()`

=== Testdurchführungsplanung

==== Wann werden Tests durchgeführt?
* *Bei Entwicklung:* Entwickler schreiben Tests parallel zur Implementierung
* *Vor Commits:* Lokale Testausführung vor jedem Commit
* *Bei Pull Requests:* Automatische Testausführung (geplant)
* *Vor Releases:* Vollständiger Testlauf mit Coverage-Analyse

==== Wer führt Tests durch?
* *Entwickler:* Unit Tests während der Entwicklung
* *Team:* Code Review mit Testüberprüfung
* *CI/CD:* Automatisierte Tests (geplant)

*Getestete Komponenten:*
